# DynamicMPNN

По статье *Multi-state Protein Design with DynamicMPNN*, arXiv:2507.21938v2 (2025). Ниже описана сохранённая версия статьи; сведения из текущего официального кода отдельно отмечены в разделе запуска.

- [PDF](DynamicMPNN_2507.21938v2.pdf)
- [Источник](https://arxiv.org/abs/2507.21938v2)
- [Ссылка для скачивания](https://arxiv.org/pdf/2507.21938v2)

## Что делает модель

DynamicMPNN решает **multi-state inverse folding**: получает несколько целевых структур белка и генерирует **одну аминокислотную последовательность, совместимую с ними одновременно**. В статье обучение и проверка сосредоточены на двух состояниях: альтернативных фолдах метаморфных белков, открытых/закрытых состояниях и движениях доменов, включая транспортёры.

В отличие от BioEmu и AlphaFlow, модель не генерирует конформационный ансамбль по последовательности. Она решает обратную задачу — проектирует последовательность по заданным конформациям. Совместимость с двумя структурами не гарантирует их равновесные вероятности или реальное переключение между ними.

## Архитектура

- **Основа:** multi-state GVP-GNN на базе идей gRNAde. Каждое состояние независимо кодируется общей сетью вместе с его **белковыми партнёрами**. Химическое окружение в описанном методе ограничено белками; малые молекулы не следует приравнивать к поддерживаемым партнёрам.
- **Энкодер и декодер:** по 8 GVP-слоёв. Узлы графа соответствуют остаткам, рёбра связывают пространственных соседей. GVP обрабатывает скалярные и векторные признаки, сохраняя согласованное преобразование векторов при вращении.
- **Объединение состояний:** признаки проектируемой цепи сопоставляют по выравниванию последовательностей и усредняют между конформациями. Позиции с пропусками учитывают через выравнивание; pooling использует nongap-остатки. Перестановка порядка состояний не меняет итоговое представление.
- **Генерация:** авторегрессивный декодер выбирает аминокислоты, учитывая уже заданные остатки и объединённую структурную информацию. Модель обучается совместному распределению последовательности, обусловленному всеми входными состояниями.

**DynamicMPNN + DSS** дополнительно обменивается признаками между состояниями после каждого слоя. В описанной scatter/gather-схеме признаки узлов проектируемых цепей усредняют, преобразуют GVP и добавляют обратно в каналы состояний; обновляются и узлы, и рёбра. Обычная DynamicMPNN обновляет признаки узлов без такого промежуточного обмена. DSS сложнее вычислительно и не показывает устойчивого преимущества по приведённым метрикам; это не просто добавление стандартного Transformer cross-attention.

## Данные и этапы обучения

| Источник | Какие данные использовали и для чего |
| --- | --- |
| **PDB / CoDNaS v2025** | Более 900 тыс. доступных **цепей «последовательность–структура»**, а не 900 тыс. PDB-записей. CoDNaS объединяет конформации с одним UniProt ID и локальным сходством последовательностей ≥95%, включая NMR-модели. Получены 46 033 кластера минимум с двумя членами, покрывающие около 75% CATH superfamilies. |
| **Multi-state training set** | Из каждого кластера выбирают пару цепей с максимальным Cα-RMSD, чтобы усилить сигнал конформационного различия. После исключения сходства с validation/test остаются **44 243 пары**. Порог фильтрации в статье сформулирован через TM-score >0,4 и сходство последовательностей >30%; структурный и последовательностный критерии не следует заменять одним из них. |
| **Single-state augmentation** | **27 394** пары «последовательность–структура» из 30%-кластеров, не представленных в multi-state training set. Они расширяют разнообразие фолдов при совместном обучении. |
| **Validation / test** | **100 / 96** белков. Источники: 92 метаморфных белка, 91 apo/holo-пример, наборы OC23 и OC85, 20 транспортёров. Самые большие межсостоянийные RMSD направлены в test; это намеренно сложный benchmark, а не случайная выборка всех белков. |
| **MD и AFDB** | Не включены в обучение этой версии. Для MD авторы указывают малое разнообразие последовательностей и редкость больших переходов в доступных траекториях; для AFDB — трудности предсказания альтернативных состояний и ограниченную дополнительную информацию о фолдах. |

Сравнивают **single-state training**, **combined training** на одиночных структурах и парах, а также предварительное обучение с последующим **multi-state fine-tuning**. Смешанные стратегии и дообучение на парах превосходят обучение только на одиночных состояниях. Лучший sequence recovery достигается вариантом *Combined Pretraining + Multi Finetuning*, поэтому лучшая стратегия зависит от выбранной метрики.

Обучение: Adam, learning rate **10⁻³**, batch size **32**, 8 GPU A100-80GB или H100-80GB. Этап заканчивают при остановке роста или снижении validation sequence recovery, обычно через **20–50 эпох**. Для итоговой multi-state оценки выбирают чекпоинт с наибольшим sequence recovery на соответствующей валидации.

**Маскирование партнёров:** последовательности белковых партнёров доступны энкодеру; скрывают последовательности цепей, имеющих >70% сходства с проектируемой цепью. Это позволяет использовать окружение, не раскрывая непосредственно целевую последовательность или её близкую копию.

## MODEL DETAILS — Appendix D, последняя страница PDF

### D.1. Признаки узлов и рёбер

| Объект | Признаки из статьи |
| --- | --- |
| **Скалярные признаки узла** | Позиционное кодирование размерности 16; backbone-углы φ, ψ, ω в шестикомпонентном представлении; виртуальный торсион κ и виртуальный угол связи α в четырёхкомпонентном представлении. |
| **Векторные признаки узла** | Вектор положения Cα, размерность 3. |
| **Скалярные признаки ребра** | Длина ребра и её представление через **32 radial basis functions (RBF)**. |
| **Векторные признаки ребра** | Направления связей между остатками в обе стороны. В Appendix D они названы единичными направлениями, но приведённая формула записана как разность координат без явной нормировки. |
| **Аугментация координат** | Гауссов шум с нулевым средним и **σ = 0,1 Å** для уменьшения переобучения на артефактах кристаллизации. Это аугментация inverse folding, а не диффузионная генерация структур. |

**Расхождение внутри статьи:** Section 2.2 указывает k-NN с **k=32**, а Appendix D.1 — **k=16**. Поэтому статья не задаёт однозначно это значение; для воспроизведения следует проверять конфигурацию выбранного чекпоинта.

### D.2. Multi-state GNN

Тензоры признаков имеют оси **«остаток × конформация × канал признаков»**; для векторных признаков есть дополнительная пространственная ось размерности 3. Message passing независимо обрабатывает конформации, сохраняя эквивариантность к перестановке их каналов. После pooling отдельная ось состояний исчезает, и декодер получает общие признаки последовательности.

### D.3. GVP и геометрическая симметрия

GVP — обобщение MLP для пары «скалярные признаки, векторные признаки». Узел собирает сообщения от соседей и обновляет свои признаки с помощью GVP; скалярные и векторные каналы обрабатываются с сохранением эквивариантности.

Базовые операции GVP O(3)-эквивариантны. Однако ориентированные двугранные углы чувствительны к отражению, поэтому полный энкодер описывается авторами как **SO(3)-эквивариантный**: он сохраняет симметрию обычных вращений, но может различать зеркальные структуры и их хиральность. При согласованном повороте входов, неизменных прочих признаках и порядке декодирования итоговые вероятности аминокислот не должны зависеть от ориентации белка в пространстве.

### D.4. Pooling без зависимости от порядка конформаций

Скалярные и векторные признаки усредняют по оси состояний: из представления «n остатков × k состояний × каналы» получают «n остатков × каналы». В статье используют только пару с максимальным RMSD, то есть **k=2**; здесь k означает **число конформаций**, а не число соседей в k-NN. Архитектурная возможность принять больше состояний не равна проверенной точности дизайна на них. Авторы обсуждают расширение pooling для гомоолигомеров как дальнейшую возможность.

## Оценка дизайна и основные результаты

Для каждого тестового белка генерируют **16 последовательностей**. Каждую проверяют двумя запусками **AlphaFold 3**: с первой и второй целевой конформацией в качестве шаблона. Сравнивают предсказание с соответствующим шаблоном по Cα-RMSD, TM-score и уверенности AF3. Это вычислительная оценка *refoldability*, а не экспериментальная демонстрация двух состояний.

Чтобы учесть влияние шаблона, ту же последовательность проверяют с **decoy** — структурно несходным шаблоном с TM-score <0,4. Decoy не обязательно физически невозможная структура: это отрицательный контроль соответствия именно целевому фолду. Для RMSD используют отношение:

$$\mathrm{RMSD}_{\mathrm{decoy\ norm}}=\frac{\mathrm{RMSD}(\mathrm{AF3}(Y,X_k),X_k)}{\mathrm{RMSD}(\mathrm{AF3}(Y,D),D)}.$$

Меньшее отношение означает лучшее соответствие целевому шаблону относительно decoy. Уверенность AF3 рассматривают отдельно; decoy normalization уменьшает проблему шаблонного смещения, но не превращает оценку в физическое доказательство.

- **Decoy-normalized RMSD:** около **0,206 против 0,275** у ProteinMPNN-MSD — снижение примерно на 25%. Сравнение Table 3 выполнено на **61** белке из 96, поскольку обработка пропусков/`X` у ProteinMPNN-MSD ограничила число дизайнов, пригодных для AF3.
- **Sequence recovery:** **42,7% против 38,0%** в Table 2 — прирост **4,7 процентного пункта**, или примерно **12% относительно baseline**, а не +12 процентных пунктов. Sequence recovery — доля восстановленных нативных аминокислот; это не доля экспериментально успешных дизайнов.
- **Ограничение сравнения:** обучение исходного ProteinMPNN не использовало тот же строгий split; авторы указывают сходство его обучающих данных с 91 из 96 тестовых белков. Более контролируемое сравнение — собственные single-state и multi-state варианты DynamicMPNN с одинаковым разделением данных.

## Ограничения

### Общие ограничения метода

- **Заданные структуры необходимы:** модель проектирует последовательность по входным конформациям, но не находит неизвестное альтернативное состояние сама.
- **Нет термодинамики или кинетики:** результат не задаёт ΔG между состояниями, их населённости, барьеры перехода или скорость переключения. Термодинамический контроль обсуждается как перспектива, а не установленная возможность этой модели.
- **Оценка в статье вычислительная:** AF3 с шаблонами может быть смещён к ним; даже хороший RMSD и высокий pLDDT не заменяют экспериментальную проверку дизайна. На сложном benchmark абсолютные RMSD остаются значительными.

### Практическое применение к разным белкам

| Белки или условия | Ограничение и практический смысл | Основание |
| --- | --- | --- |
| **Двухсостоянийные глобулярные белки** | Основная область обучения и проверки: метаморфные белки, hinges и транспортёры. Успех для конкретного нового дизайна всё равно требует проверки. | Sections 2.1 и 3. |
| **Более двух состояний / непрерывные ансамбли** | В сохранённой статье используют пары; полный кластер конформаций отложен на будущую работу. Качество для многих состояний или непрерывного ландшафта этой работой не установлено. | Section 2.1; Appendix C и D.4. |
| **Внутренне неупорядоченные белки** | Авторы отличают их непрерывные и стохастические ансамбли от упорядоченных двухсостоянийных топологий. Практический вывод: две выбранные структуры не дают подтверждённого описания всего IDP-ансамбля. | Section 2.1; явный фокус метода, а не запрет запуска. |
| **Олигомеры и белковые партнёры** | Multi-chain окружение поддерживается, поэтому общего ограничения «только одна цепь» нет. Но учёт партнёра не доказывает правильную аффинность, стехиометрию или равновесие олигомеризации. | Sections 2.2–2.3. |
| **Малые молекулы, кофакторы, нуклеиновые кислоты** | Окружение в описанном энкодере ограничено белками. Apo/holo-структуры могут быть целями дизайна, но это не явный дизайн связывания конкретного малого лиганда. | Section 2.2, multi-chain encoding. |
| **Мембранные белки** | Транспортёры входят в benchmark, поэтому считать весь класс исключённым неверно. Однако липидная мембрана явно не представлена; перенос результатов на правильную вставку в мембрану и функцию требует дополнительной проверки. | Benchmark в Section 2.1; практический вывод из представления окружения. |
| **Размер, температура, pH, дисульфидные связи** | Статья не задаёт универсальных пределов длины или отдельных запретов для этих классов. Модель не предоставляет явного управления физическими температурой и pH; точность для специфического окружения или химии нельзя вывести только из sequence recovery. | Граница выводов из описанного метода и benchmark. |

## Пример запуска из заметок

Команда ниже соответствует интерфейсу текущего официального репозитория DynamicMPNN и предназначена для **Bash/Linux** после установки пакета, получения чекпоинта и настройки `.env`. Она генерирует последовательности для примера Switch Arc (1BDT/1QTG); здесь запуск не выполнялся.

```bash
OMP_NUM_THREADS=8 CUDA_VISIBLE_DEVICES=1 dynamicmpnn-evaluate \
  eval=1bdt_1qtg \
  eval.model_ref=checkpoints/multi_chain_reload.ckpt \
  output_dir=runs/1bdt_1qtg
```

`CUDA_VISIBLE_DEVICES=1` выбирает GPU с индексом 1; его нужно изменить под доступное оборудование. Для запуска AF3-оценки официальный README дополнительно требует **`eval.af3_evaluate=true`** и настроенные пути AF3 в `.env`. Без этого флага команда не является полной проверкой refoldability через AF3. `eval.temperature` в CLI задаёт температуру сэмплирования последовательностей, а не физическую температуру белка.

Текущий официальный README также описывает single-chain чекпоинты для 2, 3 и 5 конформаций. Это сведения о доступном коде, которые не следует смешивать с двухсостоянийной проверкой в сохранённой статье v2.
